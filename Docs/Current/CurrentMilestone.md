## 目标

在既有社会沙盒上优先打磨“NPC 像有个人经历、利益和社会关系的人”的反馈质量。攻击、威胁、道歉、后退、报告和交易尝试必须形成按 NPC 个人感知隔离的连续后果；UE 继续作为世界、关系、感知与执行权威，LLM 则根据足够的个人事实、人物、关系、即时状态和近期经历，自主判断当前态度、表达和高层应对策略。

本里程碑不预写“商人必定拒绝交易”或“平民必定逃跑”的剧情链。商人、平民、守卫只是用于检验不同身份和利益是否让 LLM 作出不同、连续且符合已感知事实的判断；实际动作仍只能在 UE 已批准的能力内执行。

```text
个人感知的攻击 / 威胁 / 道歉 / 报告 / 交易尝试
  -> UE 更新有界的个人社会后果、关系与公开立场
  -> 当前 NPC 的个人 Context：事实、人物、关系、即时状态与近期经历
  -> Kimi 判定当前态度、表达和高层策略；Stub / 离线只提供明确标记的安全降级
  -> UE 校验现有受控动作并显化语言、行动和互动结果
  -> 后续个人感知继续改变该 NPC 的立场，而不广播为全局知识
```

## 协议边界

- 已确认新增独立 `POST /v2/decision`；v1 保持不变。v2 使用个人 `social_situation`、开放高层计划、表现建议和本次 UE 明确提供的有限 `available_capabilities`，完整字段与校验规则见 [Protocol.md](../Reference/Protocol.md)。
- 继续保持单 NPC、个人视角；不引入批量请求、全局共享 Observation 或模型直接执行世界行为。
- v2 只允许回显本次 UE 提供的能力实例。报告、互动立场和表现能力都必须由 UE 注册 Handler 并二次校验，未执行步骤不得被描述为已发生。

## 玩家可操作成果

- 可以连续攻击、威胁、道歉、后退、求助或尝试与商人交易，观察既往行为如何改变后续互动。
- 攻击商人后可尝试交易；交易入口只验证商人的互动立场，不创建库存、货币、物品或结算系统。
- 攻击胆小平民后，玩家可以继续接近、离开或停止，观察平民的回避、呼救和守卫介入是否只在合法感知条件下发生。

## 屏幕可见成果

- 商人、平民和守卫对同一攻击/威胁获得不同的个人事实与人物上下文，LLM 可据此作出身份、风险、关系和个人经历导致的不同语言、立场与行动。
- 第二次攻击、攻击后道歉、攻击后尝试交易等后续互动不重复首次遭遇的反应；语言与实际行动一致。
- Inspector 显示当前 NPC 已感知的相关事实、公开后果、当前立场、Decision 来源和 UE 校验结果；不显示 Prompt、隐式推理或其他 NPC 私有信息。

## 本阶段范围

### UE 权威社会后果

- 为攻击、威胁、道歉、停止/后退、有效报告和交易尝试建立有界的公开社会后果事实，包含来源、目标、时间、感知途径、严重度和处理状态。
- 在每个 NPC 自己的即时状态、关系和有界近期历史中，确定性记录重复伤害、未解决损失、已经道歉、距离变化、已发生报告与已执行动作等**事实**；必须定义去重、上限、衰减和 Reset 语义。
- Profile 提供人物、目标、价值取向和表达风格，作为 LLM 判断的依据而非 if/else 行为表；不得把具体 NPC、固定台词或固定行动顺序硬编码为剧情链。
- 只有实际看见、听见或收到 UE 已确认报告的 NPC 接收对应后果；报告是可失败的世界行为，不是全局事实捷径。

### 角色差异、Decision 与降级

- 商人、平民和守卫各自把已感知伤害、损失、关系、风险和目标带入判断。它们可能拒绝、回避、呼救、介入、警告、缓和或选择其他现有能力允许的策略，但不规定固定结果。
- Kimi 个人 Context 和固定约束明确呈现该 NPC 的已感知伤害、警告、损失、报告、交易立场和关系变化；要求模型在这些事实、人物和目标之间作出当前判断，禁止将首次遭遇、重复伤害和未解决损失视为同一情境。
- Stub 与离线降级使用同一 UE 权威社会后果快照，提供有界、可复现的安全反应；它们是服务不可用时的保底，不作为真实模型的行为剧本。
- Speech、气泡、行动记录和 Inspector 只显化公开事实、当前立场和 UE 校验结果。

### Decision v2 计划与执行

- 每次请求由 UE 构造该 NPC 的 `social_situation`：只包含自己已感知、已确认接收或已执行的高重要度社会事实，并以来源、对象、时间、摘要和重要度保持有界。
- LLM 返回开放的目标、公开理由、关注对象、连续表现参数/标签、Speech 与最多 4 个短期步骤；它可以决定策略、顺序、语气和组合，但不能创建能力、目标、资产或世界事实。
- UE 以本次 `available_capabilities` 注册表约束步骤；能力实例可表示移动、报告、互动立场或表现，但每个实例均须经过状态、目标、位置、冷却、幂等和 Handler 校验。
- UE 对计划维护提议、已接受、执行中、完成、失败、拒绝和取消结果，并把实际结果作为新的个人事实回流；新高优先级事实、状态变化、TTL 到期或失败会终止剩余步骤并重新规划。

### 实施顺序：Python 决策质量优先

- 先在 Python 以受控个人社会处境快照验证 v2 Schema、Context Builder、Kimi Planner 与 Stub：同一 NPC 的首次受击、重复受击、道歉后、交易尝试、目击/未目击和求助结果必须产生可解释的不同计划。
- Python 验收比较计划的事实引用、目标、能力选择、步骤顺序、表现倾向和安全边界，不用固定台词逐字匹配；真实 Kimi 抽样与 Stub 回归分别记录。
- 只有 Python 能稳定产出合法且角色化的 v2 计划后，UE 才实现 `social_situation` 构造、能力注册、计划执行、表情/动作适配和场景表现。客户端不替 Python 补写角色剧情。

### 最小交易立场入口

- 提供受控的交易尝试入口，结果仅为可交谈、暂缓、拒绝或需先缓和等有界互动立场。
- UE 决定互动结果；LLM 可以解释原因，但不能创建价格、物品、库存或交易成功事实。

## 明确不做

- 不建设固定剧情、任务树、犯罪/通缉系统、开放世界经济、库存、货币、物品交易或完整商店 UI。
- 不让 NPC 全局共享 Observation、隐藏状态或完整对话；模型不得自行断定报告已送达或动作已执行。
- 不新增任意动作、批量 Decision、多人协作规划、长期 SaveGame、语义检索、Embedding 或多人同步。
- 不以固定台词匹配作为验收，也不为每个输入穷举手写对话树。
