## 工作规则

- 每个工作包形成一个可审查逻辑提交，并包含适用测试与文档；全部工作包合并到里程碑集成分支，最终完整验证后再合并并统一推送。
- Task 状态变化时同步 [ProjectState.md](./ProjectState.md)；实际命令、数量、环境和结果只写入 Validation 文档。
- 本里程碑不修改 `Protocol.md`、Python/UE 协议 Schema 或 Tool 枚举；发现协议缺口时停止依赖该变更的部分并记录确认条件。
- 攻击或 Tool 拒绝测试必须同时证明生命、位置、状态版本和动作结果中适用的零副作用。
- Stub 自动化提供可重复路径但不能替代真实 Kimi 行为属性验收；真实模型不比较固定台词或固定 Tool。
- 连续调度必须通过显著事件、冷却和有界合并驱动，不允许 Tick 中逐帧请求或无上限积压。
