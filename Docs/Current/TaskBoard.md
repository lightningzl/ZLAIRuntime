## 工作规则

- 每个工作包形成一个可审查逻辑提交，并包含适用测试与文档；全部功能提交只在最终集成通过后合并并统一推送。
- Task 状态变化时同步 [ProjectState.md](./ProjectState.md)；实际命令、数量、环境和结果只写入后续 Validation 文档。
- 每个 Tool 拒绝测试必须证明零 Gameplay 副作用；只检查错误字符串不足以完成 `M8-T05`。
- Stub 自动化不能替代真实 Kimi 人工闭环；真实模型输出不可固定为唯一台词或唯一动作。
- 玩家可见气泡、动作和 Inspector 必须与 UE 实际状态一致，不能用日志或叙述代替 Gameplay 结果。
