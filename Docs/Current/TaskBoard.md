## 工作规则

- 每个工作包形成一个可审查逻辑提交，并包含适用测试与文档；全部工作包在 `codex/milestone-10` 集成分支验证后合并到 `main`，最后统一推送。
- Task 状态变化时同步 [ProjectState.md](./ProjectState.md)；实际命令、数量、环境和结果只写入 Validation 文档。
- 不修改 `Protocol.md`、Python/UE 协议 Schema 或 Tool 枚举；发现协议缺口时记录确认条件，不把跨 NPC 编排塞入协议。
- 每个 NPC 的请求、响应、Tool、攻击和降级测试必须证明不会改变其他 NPC 的状态。
- Stub 自动化提供可重复人物差异但不能替代真实 Kimi 行为属性验收；真实模型不比较固定台词或固定 Tool。
- 调度必须有全局并发、逐 NPC 在途/Pending、冷却和自动重规划硬上限，不允许逐帧请求或无上限积压。
