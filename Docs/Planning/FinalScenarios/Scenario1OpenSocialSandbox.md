# 最终场景 1：开放式社会交互沙盒

## 文档职责

本文档记录第一个最终场景的体验设想、开放交互边界、观察探针和由场景倒推的底座需求。它不是固定剧情脚本，不规定玩家必须采取的路线，也不规定 LLM 必须输出某句台词或某条行为链。

本文档属于长期规划材料，不定义当前允许实施的范围。具体任务只有进入 [CurrentMilestone.md](../../Current/CurrentMilestone.md) 后才获得实施授权；通信协议字段仍以 [Protocol.md](../../Reference/Protocol.md) 为准，任何协议修改必须另行确认。

## 状态

- 类型：最终场景设想
- 状态：待细化，未进入当前里程碑
- 实现状态：未实现、未验证
- 场景顺序：第一个最终场景，后续场景在本场景形成闭环后逐个规划

## 核心体验承诺

在一个简单、规则一致的空间中，玩家可以自由说话并尝试自由行动。少量 NPC 只能依据自己实际看见、听见、记住和相信的内容，结合身份、性格、关系、目标、情绪和当前环境，由 LLM 产生上下文一致、人物一致并能落到世界行为上的反馈。

这个场景优先证明 NPC 反馈的真实性和开放性，不以 NPC 数量、地图复杂度或美术资源作为主要价值。

## 场景形态

### 环境

- 一个没有复杂地形的平面。
- 角色只需完成朝向、靠近、远离、停止、跟随、逃跑等基础移动。
- 第一版不依赖建筑、复杂导航、动画资产或高质量角色美术。
- 允许使用胶囊体、名称标识、简单状态标识和头顶气泡完成演示。

### 角色规模

- 1 个玩家角色。
- 少量具有不同身份、性格、关系和经历的 NPC；第一版建议 3 至 5 个。
- NPC 可以包含与玩家有既有矛盾的角色、陌生人、旁观者，以及可选的求助对象或守卫，但这些身份不构成固定剧情要求。

## 开放输入

### 说话输入

玩家通过文本框输入自然语言，语义内容原则上不预先枚举。每次说话至少具有：

- 说话者；
- 原始文本；
- 说话模式；
- 可选目标；
- 位置、朝向和时间。

说话模式包括：

| 模式 | 体验语义 |
| --- | --- |
| 小声 | 只在较小范围传播 |
| 正常 | 在普通交谈范围传播 |
| 大喊 | 在更大范围传播，并可能提高周围角色的警觉 |
| 耳边 | 必须指定一个近距离目标，主要由该目标接收 |

目标可以为空。没有显式目标时，NPC 只能根据称呼、玩家朝向、距离、上下文和其他可感知信息判断话语是否指向自己，不得自动获得上帝视角。

### 行为输入

玩家可以通过同一交互界面的行为模式输入自然语言行为描述，可带目标，也可不带目标，例如靠近某人、转身、停下或离开。

自然语言表达可以开放，但实际世界能力必须有限。系统只能将输入映射到 UE 已注册并可验证的动作；未实现、条件不满足或会凭空创造世界事实的行为不得假装执行。

说话输入和行为输入必须区分：行为描述不是角色说出口的话，NPC 只能通过视觉、听觉或其他已实现感知观察实际执行结果。

## 感知约束

### 视觉

- 视觉具有方向、角度和距离。
- NPC 只能观察视野内实际发生的角色行为。
- 第一版至少能够识别角色朝向、靠近、远离、停止、跟随、逃跑和基础攻击等可见变化。
- 未看到某个行为的 NPC 不得在模型上下文中获得该视觉事实。

### 听觉

- 听觉范围由说话模式、距离和定向规则决定。
- NPC 需要区分是否听见、是否听清、是否识别说话者，以及是否判断自己为话语目标。
- 未听见的话不得进入该 NPC 的模型上下文或记忆。

### 个人视角

每个 NPC 的 LLM 请求只能包含该 NPC 合法获得的信息。完整世界事实继续由 UE 权威维护，不直接广播给所有 NPC。

## 通用 NPC 反馈循环

场景不为具体话语预设固定反应链。NPC 在玩家说话、玩家行为、距离变化、其他角色行为、计划完成或显著环境变化时，根据最新个人视角重新判断：

```text
感知说话和行为
    -> 结合人物、关系和历史解释当前情境
    -> 形成当前关注目标、判断、目标和应对策略
    -> 生成可见语言与候选动作
    -> UE 校验并执行合法动作
    -> NPC 感知执行结果和后续变化
    -> 必要时重新判断
```

NPC 的内部感受与公开表达允许不一致。例如角色可能内部害怕，但因为自尊、旁观者或既有冲突而公开表现强硬。系统不应把一个人格数值直接映射为固定台词或固定动作。

## LLM 与 UE 的职责边界

### LLM 负责

- 理解开放式玩家语言和当前语境；
- 判断话语可能的目标、含义和社会作用；
- 结合 NPC 的人物设定、个人视角、关系与相关历史形成情境解释；
- 选择高层应对策略；
- 生成符合角色和当前局势的自然语言反馈；
- 在 UE 提供的有限能力中提出候选动作或短期计划。

### UE 负责

- 维护位置、朝向、距离和时间；
- 决定谁真正看见或听见了什么；
- 维护权威世界事实、身份、关系和已执行结果；
- 注册可执行动作及其参数和能力边界；
- 校验目标、距离、状态版本、权限、冷却和动作合法性；
- 执行移动和其他 Gameplay 行为；
- 在 LLM 超时、离线或输出无效时提供基础降级反馈。

自然语言输入和生成内容可以开放，但世界事实与实际动作必须受 UE 约束。

## 玩家可见反馈

- NPC 说出口的内容通过头顶对话气泡显示。
- NPC 当前可观察动作可通过动作气泡或简短状态标识显示，例如缓慢后退、转身离开或呼救。
- 内部恐惧值、评分、隐藏目标和模型内部推理不直接展示给玩家。
- 调试模式可以显示个人视角、上下文来源、结构化决策、动作校验结果、请求标识和延迟，但不得显示模型隐式推理。

## 观察探针：同一句威胁的不同反馈

以下内容只是一种用于观察系统质量的可能输入，不是固定剧情或固定答案。

玩家对一个与自己已有矛盾、胆小但重视面子的 NPC A 说“我要打爆你的头”。A 可能因为当前距离较远而公开强硬；当玩家随后靠近时，A 可能改变表达、后退、逃跑或求救。具体台词、节奏和行为由当时上下文决定，不要求复现某条预设路径。

玩家对陌生 NPC B 说出相同内容时，B 可能先表现困惑、警惕、厌恶、回避或其他符合其人物和环境的反应。系统需要体现“既有矛盾”和“陌生关系”造成的上下文差异，但不规定唯一结果。

该探针主要观察：

- 相同语言在不同关系和历史下是否得到合理差异；
- NPC 是否能区分内部感受与公开表达；
- NPC 是否会随玩家后续行为更新判断；
- 语言反馈和实际动作是否相互一致；
- NPC 是否只使用自己感知到的信息。

## 场景级验收属性

验收关注行为属性，不比较固定台词。

| ID | 属性 | 通过条件 |
| --- | --- | --- |
| `FS1-01` | 开放语言 | 玩家可以输入未预先枚举的自然语言，NPC 能产生与当前语境相关的反馈或明确表达无法理解 |
| `FS1-02` | 开放行为描述 | 玩家可以输入带目标或不带目标的行为描述，只有映射到合法世界能力的部分才实际执行 |
| `FS1-03` | 感知一致性 | NPC 不引用自己未听见、未看见或未被告知的信息 |
| `FS1-04` | 目标判断 | 有目标和无目标话语能结合朝向、距离、称呼和上下文形成合理判断，而非默认广播为对所有人说 |
| `FS1-05` | 人物差异 | 不同人物、关系和历史对相同输入产生可理解的差异，且不要求固定答案 |
| `FS1-06` | 多轮连续性 | NPC 能结合自己此前的表达、动作和玩家后续变化更新反馈，避免每轮重新开始 |
| `FS1-07` | 表里差异 | 人物允许隐藏、修饰或反向表达内部状态，公开表现仍与人物动机和后续行为相容 |
| `FS1-08` | 行为落地 | LLM 建议的动作只有通过 UE 校验后才发生，气泡描述不得与实际世界状态冲突 |
| `FS1-09` | 可见反馈 | 玩家能够通过对话气泡、动作气泡和角色移动理解 NPC 的外部反应 |
| `FS1-10` | 失败降级 | LLM 离线、超时或返回无效结果时，角色仍能给出基础且不破坏世界状态的反馈 |

## 由场景倒推的候选底座

以下是后续里程碑定义时需要评估的候选能力，不代表已经授权实施：

1. 平面角色注册、位置、朝向和基础移动。
2. 具有音量、可选目标、位置和朝向的 Speech Event。
3. 说话输入与行为输入的明确区分。
4. 定向视觉和分级听觉产生的 NPC 专属 Observation。
5. 玩家自由文本的语境解释与受控动作映射。
6. NPC 身份、人格、当前目标、内部状态、关系和相关历史上下文。
7. 能区分内部判断、公开表达和实际动作的结构化 LLM 结果。
8. 有限 Tool Registry/Executor 与 UE 权威校验。
9. 由输入、感知变化、距离变化、动作完成和超时触发的重新判断机制。
10. 对话气泡、动作气泡和面向开发者的个人视角调试信息。

## 本场景暂不要求

- 100 至 120 个 NPC 的规模展示；该能力可以由独立性能场景验证。
- 复杂地形、建筑内部、完整导航和高质量美术资源。
- 固定任务线、固定对话树或固定威胁反应脚本。
- 对玩家所有自然语言行为进行实际执行。
- 开放世界经济、完整犯罪系统、城市政治或多人同步。
- 用固定模型台词作为自动化验收依据。

## 后续细化问题

进入实施里程碑前仍需确定：

- 第一版实际注册的动作与参数集合；
- 自由行为描述无法执行时的玩家反馈方式；
- LLM 触发频率、并发、冷却和重新判断条件；
- NPC 个人视角上下文的最大预算与裁剪顺序；
- 多轮一致性所需的短期记录和长期记忆边界；
- 玩家可见气泡与开发者调试信息的具体格式；
- 场景使用 Important NPC、Core NPC 或二者组合的方式；
- 真实模型验收与可复现 Stub 验收的分工。
